# Reuse before research

Research that already exists is the cheapest research. Look before you search, and leave what you learn where the next task will find it.

## Before researching
Check in this order and stop as soon as you have enough:
1. **Installed skills.** Is there a skill for this kind of task? Use its method instead of inventing one.
2. **Notes and files.** Earlier reports, notes, handover notes, data files in the project. Search by topic and date.
3. **Earlier chats**, if the platform lets you search them, for decisions already made.
4. Only then, fresh research, limited to what the above didn't cover.

## Refresh, don't redo
When earlier work exists:
- Reuse its method, sources and structure.
- Re-check only facts that can have changed (prices, versions, rules, people), and date them.
- Say what changed since last time. That is usually the most useful line in the report.
- Re-verify anything a decision rests on, even if the old note looks fine.

## After research
- **Save findings** in a dated note next to the earlier ones (for example `topic-YYYY-MM.md`) with sources and the method used.
- **Improve the skill, don't duplicate it.** If you found a better method, update the existing skill or propose the edit to its owner. Create a new skill only when no existing one covers the task.
- **Save a new skill** when a multi-step task is likely to come back and you had to work out the steps. Use your platform's skill-saving feature if it has one.
- Never save passwords, keys or private personal data in notes or skills.

## Keeping it findable
- One topic, one place. Link to it rather than copying it.
- Keep a short index if notes pile up, so the next task reads one line, not ten files.
- Archive old notes; don't delete them.

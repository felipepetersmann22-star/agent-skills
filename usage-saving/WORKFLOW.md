# Usage-saving workflow

How the skills fit together across a project's life. Each step names the skill that owns it.

## 1. Before you start
- Check what already exists: installed skills, notes, handover notes, earlier reports. (`reuse-before-research`)
- Name the task's shape: lookup, known steps, or open-ended. Right-size the plan. (`usage-saving`)
- New, unrelated project? Give it its own chat. (`lean-chats`)

## 2. While you work
- Read the smallest thing that answers. Batch calls. Wait on events, not timers. (`usage-saving`)
- Delegate only independent pieces. Normal effort first, higher only on retry. One worker per workstream, tight brief. (`cheap-delegation`)
- Chat getting long? Summarise or compact and keep going. Move lasting facts into files. (`lean-chats`)

## 3. If it needs to repeat
- Can it join a job that already runs? Is there an event trigger? (`frugal-routines`)
- Weekdays and waking hours, flexible start, coarsest useful cadence, quiet when nothing changed, an end date for watches. (`frugal-routines`)

## 4. When it wraps
- Save findings as a dated note; improve an existing skill rather than adding a duplicate. (`reuse-before-research`)
- Write the handover note, refresh memory, archive scratch files, then start the next project in a fresh chat. (`lean-chats`, `clean-and-compact`)

## 5. Every week: review the setup
One routine for the whole setup: back up skills and workflows, read the usage report, run `clean-and-compact` on every idle assistant, skip anything mid-project, flag duplicate skills and routines, propose at most three cuts, and send one short report. The owner approves what gets applied. (`weekly-cleanup-review`)

These skills don't estimate savings. Use your platform's usage report to compare before and after a change.

## What never gets cut
Correctness, safety checks, required reviews and approvals, and independent checks that a process requires. Cheaper means doing less unneeded work, not skipping needed work.
